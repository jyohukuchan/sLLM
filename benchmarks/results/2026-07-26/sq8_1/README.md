# SQ8_1 implementation validation

## Scope

This directory records reference-implementation evidence only.  It does not
create a candidate or release, change an active manifest, consume an
authorization, or make `SQ8_1` W8A8 eligible for production selection.

The packer accepts one deliberately narrow source contract: a verified
canonical `SQ8_0` v0.2 artifact is reconstructed row-by-row to F32 and then
requantized into a separate `SQ8_1` artifact.  Optional row compensation
remains external metadata; no compensation is written into the I8 payload.

## CPU and artifact checks

- `python3 -m unittest tests/test_sq8_1_artifact.py -v`: 5/5 pass.  The cases
  cover 1/15/16/17/31/32/33 column layouts, zero blocks, `[-127,127]`
  saturation, upward-FP16 scale boundaries, W8A16 and explicit W8A8 reference
  math, source immutability, and malformed tail rejection.
- Rust unit reader/reference tests: 4/4 pass.  Runtime CPU API tests: 2/2
  pass, including rejection of noncanonical stride and nonzero physical tail.
- `rust-reader-crosscheck.json` is the Rust reader's verification of the
  Python-packed, real 1024x5120 tensor artifact.  It checks the manifest,
  both planes, SHA-256 values, stride, and scale/padding invariants.
- `real-weight-k-proj-error.json` measures
  `model.layers.0.self_attn.k_proj.weight` (5,242,880 values) from the
  verified Qwen3-14B `SQ8_0` artifact after source reconstruction.  Weight
  relative L2 is `0.005592543546739809`, maximum absolute error is
  `0.0017452239990234375`, and post-storage clipping is zero.  This is a
  single-tensor reconstructed-SQ8_0 measurement, not a replacement for the
  design document's BF16/full-model quality evidence or an adoption gate.

The deterministic one-vector linear checks in the same JSON report relative
L2 `0.0054054985840511875` for default W8A16 and
`0.006690563471747345` for explicit W8A8.  They are tensor-level reference
checks only; no full-model logits were evaluated here.

## GPU differential and thermal record

`v620-differential.jsonl` records the successful short differential against
the C++ CPU reference.  The runner selected HIP ordinal 2 only after
`hipDeviceGetPCIBusId` returned `0000:03:00.0`, mapped that BDF to `card0`,
and read that card's `hwmon5/temp2_input` with label `junction`.  It sampled
before context creation, after upload, and before/after each of eight W8A16
and eight explicit-W8A8 launches.

| path | W8A16 relative L2 / max abs | W8A8 relative L2 / max abs | junction |
| --- | ---: | ---: | --- |
| `v620-differential.jsonl` | `6.076546605e-08` / `0.0078125` | `4.333164297e-08` / `0.0078125` | 41–42 °C; guard 85 °C |

The retained `v620-differential-attempt-1-threshold-too-tight.jsonl` shows
the initial, intentionally auditable failure: the runner used an absolute
threshold of `0.001`, while the same reduction-order comparison observed
`0.0078125` max absolute difference with relative L2 below `1e-6`.  The
runner was corrected to test before emitting a pass record and to use the
declared `0.01` absolute plus `1e-6` relative-L2 tolerances.  The succeeding
log is the result above; both runs stayed below the thermal guard.

## Offline ISA/resource audit

`static-reference-kernel/` is generated by extracting the exact HIPRTC raw
source used by the runtime, adding only the HIP header needed for an offline
translation unit, then compiling without selecting a GPU.  It covers every
runtime-whitelisted signed-dot target (`gfx1030`, `gfx1100`, `gfx1201`,
`gfx942`, and `gfx950`).  Each directory contains code objects, disassembly,
AMDGPU notes, JSON summaries, compiler versions, and SHA-256 records.

| kernel | arch | VGPR | SGPR | LDS | private / spills | dot evidence |
| --- | --- | ---: | ---: | ---: | --- | --- |
| W8A16 reference | gfx1030 | 55 | 28 | 1024 B | 0 B / 0 | no dot required |
| W8A16 reference | gfx1201 | 70 | 28 | 1024 B | 0 B / 0 | no dot required |
| explicit W8A8 reference | gfx1030 | 53 | 59 | 1024 B | 0 B / 0 | 16 `v_dot4c_i32_i8` |
| explicit W8A8 reference | gfx1201 | 53 | 59 | 1024 B | 0 B / 0 | 16 `v_dot4_i32_iu8` |

The gfx1201 disassembly records `neg_lo:[1,1,0]` on its
`v_dot4_i32_iu8` instructions, which is the signed/signed semantic selected
through `__builtin_amdgcn_sudot4(true, ..., true, ...)`.  Thus the code uses
the portable `v_dot4_i32_i8` semantic baseline while accepting the expected
VOP3P spelling on RDNA3/RDNA4.  On gfx942/gfx950 the same semantic baseline
appears as `v_dot4c_i32_i8_e32`.  `static-dot4/` independently verifies all
five target spellings in a smaller primitive probe.

## Existing-format noninterference

`SQ8_1` has a sibling manifest (`sq8_1_manifest.json`), reader module,
runtime API family, and strict `SQ8_1` identifier.  It does not reinterpret
`SQ8_0` aliases or share its payload decoder.  The test suite additionally
kept the source `SQ8_0` artifact byte-identical, verified the existing
canonical `SQ8_0` Rust tests (14/14), preserved legacy format-ID tests, and
ran existing SQ8 artifact-policy tests (13 Python tests total with the format
tests).  `AQ4_0` received no ABI, artifact, or dispatch change.
